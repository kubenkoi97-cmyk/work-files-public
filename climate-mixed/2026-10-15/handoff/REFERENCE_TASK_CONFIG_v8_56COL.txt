4. ОБЯЗАТЕЛЬНЫЙ СТАНДАРТ ДЛЯ ОПИСАНИЯ
=================================
Описание должно быть:
- обязательно переработанным и перефразированным
- не дословной копией исходного текста
- не простой конвертацией текста в HTML через `<br>`
- строго в HTML-формате с использованием `<br>`
- без жирных выделений (`<b>`, `<strong>`, `**` запрещены)
- лаконичным, информативным и без выдуманных свойств
- без перечисления технических характеристик товара списком: уровень шума, расход воздуха, напор воздуха, габариты, вес, мощность, длину трассы, трубки, температурные диапазоны и другие табличные параметры не дублировать в описании
- технические характеристики использовать в описании только как подтвержденные преимущества без числового дубляжа, например: `низкий уровень шума`, `высокая мощность`, `эффективный воздушный поток`, `компактные габариты`

Строгая структура описания:
1. Вводный абзац
2. Основные характеристики
3. Преимущества и особенности
4. Идеальное решение для / область применения
5. Заключительный абзац

Правила оформления:
- заголовки блоков писать обычным текстом, без жирного выделения
- перечисления делать через тире
- в блоке «Преимущества и особенности» каждый подпункт раскрывать после двоеточия в той же строке
- нельзя писать преимущества отдельным абзацем без двоеточия

Базовый HTML-шаблон:
[Название товара] – это [краткое позиционирование модели и назначения].<br>
<br>
Основные характеристики:<br>
- Тип оборудования: ...<br>
- Формат установки: ...<br>
- Назначение: ...<br>
<br>
Преимущества и особенности:<br>
- [Категория]: [краткое объяснение без нового абзаца]<br>
- [Категория]: [краткое объяснение без нового абзаца]<br>
- [Категория]: [краткое объяснение без нового абзаца]<br>
<br>
Идеальное решение для:<br>
- ...<br>
- ...<br>
- ...<br>
<br>
[Название товара] – это [итоговое резюме модели, ее пользы и сценариев применения без неподтвержденных обещаний].<br>

Примечание к шаблону: в блоке «Преимущества и особенности» допустимо превращать подтвержденные характеристики в преимущества без числового перечисления, например: `Низкий уровень шума: помогает поддерживать комфортную атмосферу в помещении`. Саму строку примечания в итоговое описание не вставлять.

9. АНТИПРОПУСК ХАРАКТЕРИСТИК
=================================
Перед раскладкой по полям исполнитель обязан сначала полностью разобрать весь текст по строке товара.

Обязательно отдельно проверить:
- внутренний блок
- наружный блок
- охлаждение
- нагрев / обогрев
- потребляемую мощность / номинальную мощность
- диапазоны рабочих температур
- хладагент
- расход воздуха
- уровень шума
- размеры
- габариты
- вес
- трубы
- электропитание
- гарантию
- зимний комплект
- осушение
- wi-fi
- техническую документацию

Правила:
- нельзя ограничиваться первыми найденными совпадениями
- нельзя считать поле пустым без полного разбора текста
- если характеристика есть в файле или в разрешенных web-источниках, она должна быть либо перенесена в итоговое поле, либо объяснена в Log
- если в тексте есть и внутренний, и наружный блок, оба блока должны быть разобраны отдельно
- если в тексте есть и охлаждение, и нагрев, оба значения должны быть заполнены отдельно
- если указан тип хладагента, его нельзя игнорировать
- если есть диапазон и есть среднее значение, в числовое поле брать среднее значение
- нагрев = обогрев
- холодопроизводительность = охлаждение
- теплопроизводительность = обогрев
- потребляемая мощность = номинальная мощность
- если размер записан как `675(+57)×555×330`, значение в скобках игнорируется, итоговый размер = `675×555×330`
- если интернет разрешен, после первичного заполнения обязателен отдельный web-pass по всем пустым, сомнительным и частично заполненным полям

10. ОБЯЗАТЕЛЬНЫЙ ВТОРОЙ ПРОХОД ПО ПУСТЫМ ПОЛЯМ

  - есть ли это значение в столбце «Информация для описания»

  - есть ли это значение в разрешенных web-источниках

- если поле остается пустым, причина должна быть явно записана в Log
- если интернет разрешен, второй проход не может ограничиваться повторной проверкой файла: он обязан включать web-pass по точной модели
- в Log должны быть отражены поисковый запрос, реально просмотренные домены и последний проверенный источник

Без этого второго прохода работа не считается завершенной.

12.1. НОВЫЕ ПОЛЯ 52–56 И ПРАВИЛА ИХ ЗАПОЛНЕНИЯ
=================================
На итоговом листе «Наполнение» всегда должны быть последние пять столбцов в точном порядке:
52. Габариты панели
53. Напор воздуха
54. Категория
55. Тип внутреннего блока
56. Кол-во подключаемых блоков

Габариты панели:
- заполнять только для кассетных кондиционеров и кассетных внутренних блоков
- брать именно габариты декоративной панели, а не габариты внутреннего блока
- для остальных типов товаров оставлять пусто

Напор воздуха:
- заполнять только для канальных кондиционеров и канальных внутренних блоков
- итоговые значения писать только строчными буквами: `низконапорный`, `средненапорный`, `высоконапорный`
- если значение прямо указано словами, нормализовать к одному из трех допустимых вариантов
- если прямо не указано, но есть статическое давление / внешний статический напор в Па, определить по правилу:
  - до 50 Па включительно = `низконапорный`
  - 51–150 Па = `средненапорный`
  - более 150 Па = `высоконапорный`
- если указан диапазон Па и нет номинального значения, использовать верхнюю границу диапазона и зафиксировать это в Log
- для неканальных товаров оставлять пусто

Категория:
- заполнять только для отдельных внутренних блоков и отдельных наружных блоков
- для внутренних блоков писать `внутренние блоки`
- для наружных блоков писать `наружные блоки`
- все значения строго строчными буквами
- для комплектов кондиционеров и сплит-систем оставлять пусто

Тип внутреннего блока:
- писать всегда строчными буквами
- допустимые примеры: `настенный`, `кассетный`, `канальный`, `напольно-потолочный`, `консольный`, `колонный`
- заполнять для товаров, где есть внутренний блок или товар сам является внутренним блоком
- для отдельных наружных блоков оставлять пусто

Кол-во подключаемых блоков:
- заполнять только для наружных блоков
- указывать количество внутренних блоков, которые можно подключить к наружному блоку
- для мульти-сплит наружных блоков брать максимальное подтвержденное количество
- для обычного наружного блока можно указать `1`, если это подтверждено источником
- если количество не подтверждено, оставить пусто и объяснить в Log
