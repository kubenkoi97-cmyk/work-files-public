# MASTER_STANDARD.md
## Единый стандарт трехэтапного Excel-конвейера по товарам климатической техники
## Версия: FILE / WEB / MIXED / HARD AUDIT / ANTI-SKIP / V8 56 COLUMNS / CAPITALS

---

## 1. Назначение

Этот стандарт описывает полный рабочий процесс обработки товаров климатической техники в Excel.

Базовый конвейер всегда состоит из 3 этапов:
1. **Сбор данных**
2. **Нормализация**
3. **Наполнение**

Дополнительно всегда создаются листы:
- **Источники**
- **Log**

Минимальный состав итоговой книги:
- Сбор данных
- Нормализация
- Наполнение [Бренд первого товара]
- Источники
- Log

Если бренд первого товара нельзя надежно определить:
- Наполнение Без бренда
- Товары Без бренда.xlsx

Если бренд первого товара определен:
- Наполнение [Бренд первого товара]
- Товары [Бренд первого товара].xlsx

---

## 2. Обязательный первый шаг: определить режим источника

Перед началом любой задачи обязательно определить **режим источника**.
Без этого работу начинать нельзя.

Допустимы только 3 режима:
- **FILE** — данные берутся из файла пользователя
- **WEB** — данные берутся из интернета
- **MIXED** — часть данных из файла, часть из интернета

Если пользователь не указал режим, исполнитель обязан сначала спросить:

**Источник данных:**
1. FILE — из файла
2. WEB — из интернета
3. MIXED — смешанный режим

### 2.1. Правила режима FILE
В режиме FILE:
- характеристики брать из столбца **«Характеристики»**
- описание строить только на основе столбца **«Информация для описания»**
- описание нельзя переносить дословно: его нужно **обязательно переработать, перефразировать и привести к стандарту описания из раздела 7.7**
- простая замена переносов строк на `<br>` не считается выполнением задачи
- техническую документацию брать из столбца **«Техническая документация»**
- интернет не использовать
- ничего не добирать из внешних источников
- если данных в файле нет, поля оставлять пустыми

### 2.2. Правила режима WEB
В режиме WEB:
- действует полный интернет-сценарий
- характеристики ищутся в интернете
- описание строится по интернет-источникам
- описание нельзя собирать механической склейкой фраз: его нужно **обязательно переработать, перефразировать и привести к стандарту описания из раздела 7.7**
- применяются правила точной карточки товара, глубокого парсинга и расширенного поиска
- если в задаче заданы приоритетные сайты, их нужно проверить в первую очередь
- если на приоритетных сайтах есть скрытые блоки, вкладки, аккордеоны, кнопки «Развернуть», «Подробнее», «Показать ещё», «Характеристики», «Описание», «Параметры», «Технические характеристики», исполнитель обязан открыть их и дочитать данные до конца
- если на приоритетных сайтах данных недостаточно, нельзя завершать поиск преждевременно: нужно продолжать поиск по дополнительным доступным сайтам в соответствии с правилами разделов 5.4, 5.5, 5.5.1 и 5.5.2

### 2.3. Правила режима MIXED
В режиме MIXED:
- пользователь обязан явно указать, **что именно брать из файла, а что из интернета**
- без такой карты источников работу начинать нельзя
- исполнитель не имеет права сам решать, какие поля брать из файла, а какие из интернета
- если карта источников задает FILE→WEB, сначала нужно максимально полно извлечь все подтвержденные данные из файла и только затем дозаполнять реально отсутствующие или не поддающиеся надежному извлечению поля из интернета
- если поле есть в файле и его можно надежно извлечь, оставлять его пустым и сразу переходить к интернету запрещено
- интернет в MIXED используется только для добивки недостающих полей, а не вместо обязательного полного разбора файла
- если карта источников содержит FILE→WEB, WEB или иное разрешение интернета хотя бы для части полей, после разбора файла обязателен отдельный web-pass по пустым, сомнительным и частично заполненным полям
- отсутствие документированного web-pass в MIXED автоматически означает, что задача не завершена



### 2.4. Обязательный web-pass при разрешенном интернете
Если режим = **WEB**, либо режим = **MIXED** и карта источников разрешает интернет хотя бы для части полей, web-поиск не является опцией.

Исполнитель обязан выполнить отдельный **web-pass** после полного разбора файла и после первичного заполнения полей.

Web-pass обязателен для:
- всех пустых полей
- всех сомнительных полей
- всех частично заполненных полей
- всех полей, где значение в файле выглядит неполным, обрезанным, конфликтным или недостаточно надежным
- всех полей, для которых карта источников задает **FILE→WEB**, **WEB** или иной вариант с разрешенным интернетом

Минимальные требования к web-pass:
1. сначала выполнить полный извлекающий разбор исходного файла по строке товара
2. затем собрать список полей, которые уходят на web-проверку
3. искать **точную карточку модели**, а не ограничиваться каталогом или серией, если карточка существует
4. сначала проверять приоритетные сайты
5. обязательно раскрывать скрытые блоки, вкладки и аккордеоны: «Характеристики», «Описание», «Подробнее», «Развернуть», «Показать ещё» и аналогичные
6. если данных недостаточно, проверять минимум установленное задачей число дополнительных доступных доменов
7. по каждому полю фиксировать в Log, что именно искалось, где искалось, что найдено, куда перенесено, почему не перенесено и какой источник был последним проверенным

Финализация запрещена, если интернет был разрешен, но web-pass не выполнен либо не отражен в Log и на листе «Источники».

## 3. Главные принципы работы

Исполнитель обязан:
- работать строго по исходным строкам Excel-файла пользователя
- не менять порядок строк
- не добавлять новые товары
- не смешивать данные разных моделей
- не брать похожие или приблизительно совпадающие модели
- не придумывать характеристики
- не использовать источник, который запрещен выбранным режимом
- не завершать задачу без итоговой самопроверки
- не считать характеристику отсутствующей, пока не выполнены все обязательные проверки этого стандарта
- сначала выполнить полный извлекающий разбор текста по строке товара, а уже потом раскладывать значения по итоговым полям
- если характеристика найдена в разрешенном источнике, либо перенести ее в соответствующее поле, либо явно зафиксировать причину пропуска в Log
- не считать аудит выполненным по общей формулировке; аудит должен быть выражен в явных проверках по строкам, полям, источникам и пустым значениям
- не считать файл финальным, пока отдельно не сформирован и не проверен список пустых, сомнительных и частично заполненных полей
- если интернет разрешен, выполнять web-pass как обязательный контрольный этап, а не как необязательную добивку
- считать MIXED/WEB-задачу завершенной только после документированного web-pass по всем пустым, сомнительным и частично заполненным полям

Запрещено:
- угадывать значения
- подменять данные файла интернетом в режиме FILE
- использовать интернет в режиме FILE
- нарушать карту источников в режиме MIXED
- менять значения полей, которые должны идти строго из исходного Excel
- выдергивать только первые найденные совпадения из текста и игнорировать остальной контекст
- оставлять пустое поле без отдельной проверки и без объяснения причины
- писать, что работа завершена, если не выполнен полный второй проход по пустым полям
- выдавать файл как финальный, если в нем есть строки со статусом «Выполнено частично», «Требует исправления» или «Невозможно выполнить» без отдельного явного предупреждения пользователю
- завершать задачу после одного только разбора файла, если карта источников требует FILE→WEB или разрешает интернет для недостающих полей
- писать «не найдено», если не отражено, какие web-источники реально были проверены и какой источник был последним проверенным

## 4. Источники истины по типам данных

### 4.1. Поля, которые всегда брать строго из исходного Excel
Независимо от режима, если эти поля есть в исходном Excel, они должны идти строго оттуда:
- Поставщик
- Артикул
- Сортировка
- Цена

### 4.2. Карта источников в режиме FILE
- Характеристики для нормализации → столбец **«Характеристики»**
- Описание (исходный материал) → столбец **«Информация для описания»**
- Описание (итоговый текст) → только после обязательной переработки по стандарту из раздела 7.7
- TECH_DOCUMENTATION → столбец **«Техническая документация»**
- Поставщик → исходный Excel
- Артикул → исходный Excel
- Сортировка → исходный Excel
- Цена → исходный Excel
- Интернет → запрещен

### 4.3. Карта источников в режиме WEB
- Характеристики → интернет
- Описание → интернет
- TECH_DOCUMENTATION → по правилам задачи, если применимо
- Поставщик → исходный Excel
- Артикул → исходный Excel
- Сортировка → исходный Excel
- Цена → исходный Excel

### 4.4. Карта источников в режиме MIXED
Карта задается пользователем на каждую задачу.
Пример:
- Характеристики = FILE
- Описание = FILE
- TECH_DOCUMENTATION = FILE
- Недостающие технические поля = WEB
- Серия = WEB

### 4.5. Обязательное правило проверки наличия характеристики
Если характеристика присутствует хотя бы в одном разрешенном источнике для данной задачи:
- в столбце **«Характеристики»**
- в столбце **«Информация для описания»**
- в столбце **«Техническая документация»**
- на карточке товара
- во вкладках «Характеристики», «Описание», «Подробнее», «Развернуть»
- в технических таблицах
- в текстовых блоках под карточкой
- в резервных интернет-источниках, если интернет разрешен

то она должна быть:
- либо перенесена в соответствующее итоговое поле,
- либо явно отражена в Log с объяснением, почему итоговое поле осталось пустым.

Оставлять поле пустым без отдельной проверки этих зон запрещено.

## 5. Этап 1 — Сбор данных

### 5.1. Общие правила
Перед любым сбором данных обязательно:
1. программно прочитать исходный Excel
2. сохранить исходный порядок строк
3. сохранить все исходные столбцы
4. зафиксировать исходные значения критичных полей

### 5.2. Структура листа «Сбор данных»
На листе «Сбор данных» сохраняются все исходные столбцы.

Справа добавляются служебные столбцы:
- Ссылка
- Источник
- Статус
- Комментарий
- Режим источника

Если пользователь хочет, допустимо также оставлять или создавать рабочие поля:
- Характеристики
- Описание

Но при режиме FILE, если эти столбцы уже есть во входном файле, они считаются исходными и не дублируются.

### 5.3. Заполнение листа «Сбор данных» в режиме FILE
- **Характеристики** берутся из столбца «Характеристики» входного файла
- **Описание** на этом этапе фиксируется только как исходный материал из столбца «Информация для описания»
- итоговое **Детальное описание** на этапе «Сбор данных» еще не считается готовым и должно быть отдельно переработано по стандарту из раздела 7.7
- **Ссылка** = пусто
- **Источник** = Файл пользователя
- **Статус**:
  - Найдено — если по строке есть достаточные данные
  - Частично найдено — если часть ключевых данных отсутствует
  - Не найдено — если данных почти нет
- **Комментарий** = какие именно данные взяты из файла, достаточно ли материала для переработки описания и чего не хватает
- **Режим источника** = FILE

### 5.4. Заполнение листа «Сбор данных» в режиме WEB
- искать точную карточку товара по модели
- не использовать страницу серии или каталога как полноценную замену карточке, если карточка существует
- открывать вкладки «Характеристики» и «Описание», если они есть
- раскрывать скрытые блоки, спойлеры, аккордеоны
- проверять технические таблицы внутреннего и наружного блока
- фиксировать основной источник и резервные источники
- если ключевых данных не хватает — продолжать поиск по другим доменам

### 5.5. Расширенный поиск в режиме WEB
Если по модели не найдены ключевые поля:
- Охлаждение, кВт
- Обогрев, кВт
- Номинальная мощность, кВт
- Электропитание, В
- Диаметр труб хладагента

то поиск нельзя считать завершенным после 1–2 сайтов.

Нужно продолжать поиск до одного из двух состояний:
- нужные данные найдены и подтверждены
- реально проверены до 15 доступных открывающихся доменов

Недоступные, закрытые, защищенные, не открывшиеся сайты в зачет не идут.

### 5.5.1. Приоритетные сайты и глубина просмотра
Если пользователь указал приоритетные сайты, исполнитель обязан:
- сначала проверить именно их
- не ограничиваться каталогом или превью-карточкой
- открыть страницу точной модели
- открыть блоки «Характеристики», «Описание», «Подробнее», «Развернуть», «Показать ещё» и аналогичные элементы
- проверить скрытые таблицы и текстовые секции
- только после этого переходить к резервным доменам

Если данных на приоритетных сайтах не хватает, а интернет разрешен:
- исполнитель обязан проверить не менее 5 дополнительных доступных открывающихся сайтов, если пользователь не задал более жесткое требование
- число реально просмотренных доступных доменов должно быть отражено в Log
- поиск нельзя завершать на основании того, что «похоже, данных нет», если скрытые блоки и дополнительные сайты не проверены



#### 5.5.1.A. Обязательный web-pass по проблемным полям
Если интернет разрешен задачей, после полного разбора текста и после первичного заполнения исполнитель обязан выполнить **отдельный web-pass** по всем пустым, сомнительным и частично заполненным полям.

В рамках этого этапа обязательно:
- составить список полей, ушедших на web-проверку
- искать по точной модели и, при необходимости, по точной связке серия + модель
- сначала пройти приоритетные сайты
- только после этого переходить к резервным доменам
- по проблемной строке фиксировать число реально просмотренных доступных доменов
- не считать web-pass выполненным, пока в Log не зафиксированы: поисковая задача, просмотренные домены, найденные значения, незаполненные поля и последний проверенный источник

Запрещено:
- ограничиваться одним лишь столбцом «Характеристики», если интернет разрешен
- считать, что данных «достаточно», пока web-pass не завершен документированно
- завершать обработку проблемной строки, если для нее не отражено, какие web-источники были реально просмотрены


### 5.5.2. Обязательный полный извлекающий разбор текста
Перед заполнением любых полей по строке товара исполнитель обязан сделать **полный извлекающий разбор** всех доступных текстов и таблиц по этой строке, а уже потом раскладывать значения по полям.

Обязательное правило:
- нельзя выдергивать только первые совпадения из текста
- нельзя останавливаться после нахождения части характеристик
- нельзя считать задачу выполненной, если из текстового блока извлечены только внутренний блок, но не наружный, или только охлаждение, но не нагрев/обогрев
- нельзя считать характеристику отсутствующей до окончания полного разбора всего текста

Нужно сначала пройти весь текст целиком и извлечь все подтвержденные сущности:
- бренд
- серия
- модель
- режим работы
- наименование элемента
- инвертор
- габариты панели
- напор воздуха
- категория
- тип внутреннего блока
- кол-во подключаемых блоков
- площадь
- охлаждение
- обогрев / нагрев
- потребляемая мощность / номинальная мощность
- электропитание
- расход воздуха
- уровень шума
- цвет
- хладагент
- wi-fi
- размеры внутреннего блока
- размеры наружного блока
- вес внутреннего блока
- вес наружного блока
- длина трассы / перепад высот
- диапазон рабочих температур на охлаждение
- диапазон рабочих температур на нагрев
- диаметр труб
- гарантия
- страна изготовитель
- зимний комплект
- осушение
- техническая документация

Только после этого разрешено переходить к этапу раскладки по итоговым столбцам.

### 5.5.3. Обязательный словарь соответствий и синонимов
Исполнитель обязан распознавать и считать эквивалентными следующие формулировки:

#### 5.5.3.1. Теплопроизводительность
- **нагрев = обогрев**
- **производительность на нагрев = обогрев, кВт**
- **теплопроизводительность = обогрев, кВт**

#### 5.5.3.2. Холодопроизводительность
- **охлаждение = холодопроизводительность**
- **производительность на охлаждение = охлаждение, кВт**

#### 5.5.3.3. Потребляемая мощность
- **потребляемая мощность = номинальная мощность**
- если указаны отдельные значения по режимам, в поле **«Номинальная мощность, кВт»** брать значение потребляемой мощности **на охлаждение**

#### 5.5.3.4. Рабочие температуры
- **нагрев = обогрев**
- если диапазоны указаны подряд как охлаждение, затем нагрев, то второй диапазон должен идти в поле нагрева / обогрева, а не теряться

#### 5.5.3.5. Хладагент
Обязательно распознавать и не игнорировать:
- R32
- R410A / R410
- R454B
- и другие явно указанные типы

Если тип хладагента указан в любом разрешенном источнике, поле не должно оставаться пустым.

### 5.5.4. Обязательное правило по среднему значению и диапазонам
Если характеристика дана одновременно:
- как диапазон,
- и как отдельное номинальное / среднее / стандартное значение,

то в итоговое числовое поле брать **среднее / номинальное значение**, а диапазон переносить только в специальное поле диапазона, если такое поле предусмотрено.

Запрещено:
- подставлять диапазон вместо среднего значения
- подставлять крайнее значение диапазона вместо среднего
- игнорировать среднее значение, если оно присутствует в тексте

### 5.5.5. Обязательный разбор внутреннего и наружного блока
Если в тексте встречаются блоки:
- **внутренний блок**
- **наружный блок**

то исполнитель обязан разобрать **оба** блока отдельно.

Если размеры указаны для двух блоков, запрещено:
- переносить только внутренний блок
- оставлять наружный блок пустым
- путать местами размеры внутреннего и наружного блока
- заполнять только поле общих габаритов без раскладки по ширине / высоте / глубине

Если в строке есть данные наружного блока, должны быть проверены и при наличии заполнены:
- Ширина наружного блока, мм
- Высота наружного блока, мм
- Глубина наружного блока, мм
- Габариты наружного блока (ШxВxГ), мм
- Вес наружного блока, кг

То же правило действует для внутреннего блока.

### 5.5.6. Обязательный разбор сложных форматов размеров
Исполнитель обязан распознавать размеры не только в простом виде `Ш×В×Г`, но и в усложненных форматах, например:
- `675×555×330`
- `675 x 555 x 330`
- `675х555х330`
- `675(+57)×555×330`
- `798/295/232`
- `798*295*232`

Если формат нестандартный, это не основание пропускать значение.

Правило обработки:
- нужно попытаться нормализовать формат
- если часть значения дана в скобках, это не повод оставлять все поле пустым
- если размер записан в формате `675(+57)×555×330`, значение в скобках должно быть проигнорировано; итоговый размер записывается как `675×555×330`
- при раскладке по отдельным полям нужно брать только значения вне скобок
- если нельзя надежно разложить нестандартный размер по отдельным полям без риска искажения, тогда:
  - минимум нужно заполнить общее поле габаритов
  - а в **Log** зафиксировать, что отдельные поля требуют ручной проверки

Запрещено из-за сложного формата полностью терять характеристику.

### 5.5.7. Обязательная перекрестная проверка между полями
После первичного извлечения исполнитель обязан сделать перекрестную сверку:

#### 5.5.7.1. Если есть общий размер блока
И есть строка формата `Ш×В×Г`, то должны быть проверены и по возможности заполнены:
- отдельные поля ширины / высоты / глубины
- общее поле габаритов

#### 5.5.7.2. Если есть размеры блока
Должен быть проверен и вес этого же блока в том же тексте

#### 5.5.7.3. Если есть охлаждение
Должен быть отдельно проверен обогрев / нагрев

#### 5.5.7.4. Если есть диапазон рабочих температур
Должны быть отдельно проверены:
- охлаждение
- нагрев / обогрев

#### 5.5.7.5. Если есть трубки в дюймах
Они обязательно должны быть:
- распознаны
- переведены в мм на этапе Нормализация
- записаны с десятичной запятой на этапе Наполнение

### 5.5.8. Обязательный второй проход по пустым полям
После первичного заполнения строки исполнитель обязан сделать **второй проход только по пустым или сомнительным полям**.

Для каждого пустого поля нужно отдельно проверить:
1. есть ли это значение в столбце **«Характеристики»**
2. есть ли это значение в столбце **«Информация для описания»**
3. есть ли это значение в **«Технической документации»**
4. если режим разрешает интернет — есть ли это значение в интернете
5. выполнен ли по этому полю обязательный web-pass
6. если значение найдено, почему оно не перенесено

Если интернет разрешен, второй проход по пустым полям не может ограничиваться повторной проверкой файла: он обязан включать документированный web-pass.

До выполнения этого второго прохода строку нельзя считать завершенной.

### 5.5.9. Обязательное сравнение «исходный текст → итоговые поля»
По каждой строке товара исполнитель обязан делать контрольную сверку:

**если в исходном тексте или разрешенных web-источниках явно есть характеристика, то в результате должно быть одно из двух:**
- либо заполнено соответствующее итоговое поле,
- либо есть запись в Log, почему поле не заполнено.

Иначе строка считается обработанной некорректно.

### 5.6. Высота строк
На листе «Сбор данных» высота всех строк всегда = **15**.
Автоподбор высоты запрещен.

### 6.3. Обязательные правила нормализации
1. Мощности — в кВт, с двумя знаками после точки
2. Расход и шум — через /, без пробелов, в подтвержденном порядке

   - 220-240
   - 380-415
4. Номинальная мощность = потребляемая мощность на охлаждение
5. Площадь:
   - брать подтвержденное значение, если оно есть
   - если его нет, допускается расчет от охлаждения
   - площадь ≈ охлаждение × 10
   - округление до ближайшего значения, кратного 5
6. Режим работы:
   - итоговое значение для поля «Режим работы [PROP_423]» всегда записывать как `тепло-холод`
   - не писать `охлаждение/обогрев`, `тепло/холод`, `охлаждение`, `обогрев` или `нагрев` в итоговом поле режима работы

7. Инвертор:
   - итоговое значение всегда писать только строчными буквами: `да` или `нет`
   - запрещены варианты `Да`, `Нет`, `есть`, `инверторный`, `on/off` в итоговом поле «Инвертор [PROP_17]»
8. Wi‑Fi:
   - подготовка / ready / опция = опция
   - встроенный = встроен
9. Нагрев = обогрев
10. Холодопроизводительность = охлаждение
11. Теплопроизводительность = обогрев
12. Если одновременно указаны диапазон и среднее значение, в итоговое числовое поле переносить среднее значение
13. Если тип хладагента указан в тексте, он должен быть явно перенесен в поле «Хладагент»
14. Габариты панели заполнять только для кассетных кондиционеров и кассетных внутренних блоков
15. Напор воздуха заполнять только для канальных кондиционеров и канальных внутренних блоков; значение всегда строчными буквами: `низконапорный`, `средненапорный` или `высоконапорный`
16. Категория заполняется только для отдельных внутренних и наружных блоков; допустимы только строчные значения `внутренние блоки` или `наружные блоки`
17. Тип внутреннего блока всегда писать строчными буквами: `настенный`, `кассетный`, `канальный`, `напольно-потолочный` или другой подтвержденный тип
18. Кол-во подключаемых блоков заполнять только для наружных блоков и только подтвержденным числом внутренних блоков, которые можно подключить к наружному блоку

### 6.4. Обязательное правило по трубам
Если диаметр труб указан в дюймах, на этапе Нормализации он обязан быть переведен в мм по таблице:
- 1/4 = 6,35
- 3/8 = 9,52
- 1/2 = 12,7
- 5/8 = 15,87
- 3/4 = 19,05

На вкладке «Нормализация» нельзя оставлять итоговые значения в дюймах.

### 6.5. Обязательное правило по габаритам
Если размер записан с дополнительным значением в скобках, например:
- `675(+57)×555×330`

то:
- значение в скобках игнорируется
- итоговый размер нормализуется как:
  - `675×555×330`
- отдельные поля ширины / высоты / глубины заполняются только значениями вне скобок

### 6.6. Высота строк
На листе «Нормализация» высота всех строк всегда = **15**.

- Если новое поле неприменимо к конкретному товару, поле оставлять пустым, а причину неприменимости фиксировать в Log при режиме проверки пустых полей

### 7.4. Наименование элемента
Наименование элемента всегда должно быть полным, но без названия серии.

Обязательное правило:
**[полный тип товара] [бренд] [модель]**

Требования:
- не включать название серии в «Наименование элемента», даже если серия подтверждена и заполняется в отдельном поле «Серия [PROP_422]»
- модель указывать полностью, включая обозначения внутреннего и наружного блока, если товар является комплектом
- не удалять важные суффиксы модели, индексы цвета, обозначения `IN`, `OUT`, `W`, `B`, `R32` и аналогичные подтвержденные части модели
- не дублировать бренд, тип или модель
- не подставлять в название рекламные формулировки и преимущества
- первое слово в «Наименование элемента» всегда писать с заглавной буквы: `Настенный кондиционер ...`, `Внутренний блок мультисистемы ...`, `Наружный блок мультисистемы ...`, `Кассетный кондиционер ...`
- если тип товара начинается со строчной буквы, перед финализацией обязательно исправить регистр без изменения модели и бренда

### 7.5. Символьный код
Формировать только из модели:
- нижний регистр
- символы /, _, пробел → заменять на -

### 7.6. TECH_DOCUMENTATION
Если в исходном файле в строке товара в столбце **«Техническая документация»** есть HTML, он должен быть **обязательно перенесен** в поле:
**Техническая документация [TECH_DOCUMENTATION]**

Если в этом столбце пусто:
- ничего не добавлять
- не выдумывать
- не заменять внешними данными в режиме FILE

### 7.7. Детальное описание
Детальное описание всегда является **отдельным итоговым текстом**, а не копией исходного материала.
Независимо от режима источника, описание должно быть **обязательно переработано, перефразировано и приведено к единому стандарту**.

Обязательные правила для всех режимов:
- описание нельзя переносить дословно из файла или из интернет-источника
- простая замена переносов строк на `<br>` не считается выполнением задачи
- описание должно быть в HTML-формате с использованием `<br>`
- детальное описание всегда должно начинаться с заглавной буквы
- название товара в первом абзаце и в заключительном абзаце описания должно начинаться с заглавной буквы и совпадать по смыслу с «Наименование элемента»
- строки обычного текста после `<br>`, включая пункты после маркера `-`, должны начинаться с заглавной буквы, если это не технический код, модель, единица измерения или другое значение, для которого строчный регистр обязателен
- жирные выделения (`<b>`, `<strong>`, markdown `**`) запрещены
- текст должен быть лаконичным, информативным и без выдуманных свойств
- в детальном описании нельзя перечислять технические характеристики товара как табличные значения: уровень шума, расход воздуха, напор воздуха, габариты, вес, мощность, длину трассы, диаметры труб, рабочие температуры и подобные параметры нельзя выносить списком с цифрами
- технические характеристики должны оставаться в отдельных полях «Наполнение», а не дублироваться в описании
- подтвержденные свойства можно использовать как преимущества без табличного перечисления значений: например, `низкий уровень шума`, `высокая мощность`, `эффективный воздушный поток`, `компактные габариты`, `удобство монтажа`
- если преимущество основано на характеристике, оно должно быть сформулировано смыслово и без неподтвержденных обещаний; числовое значение добавлять в описание нельзя, если пользователь отдельно не запросил числовые значения в тексте
- структура должна быть строго фиксированной и идти в следующем порядке:
  1. вводный абзац
  2. блок **Основные характеристики:**
  3. блок **Преимущества и особенности:**
  4. блок **Идеальное решение для:**
  5. заключительный абзац
- внутри блоков перечисления оформлять через тире
- в блоке **Преимущества и особенности:** каждый подпункт писать в строке после тире, а содержимое подпункта раскрывать **после двоеточия в этой же строке**, а не отдельным абзацем
- нельзя делать жирные подзаголовки или декоративные маркеры
- нельзя добавлять неподтвержденные характеристики, функции, классы эффективности, площади и иные свойства
- если подтвержденного материала для полноценного описания не хватает, описание нельзя дополнять выдумкой: нужно либо использовать разрешенный резервный источник, либо оставить поле пустым и отметить причину в Log

Базовый шаблон итогового описания:
[Название товара] – это [краткое позиционирование модели и назначения].<br>
<br>
Основные характеристики:<br>
- Тип оборудования: ...<br>
- Формат установки: ...<br>
- Назначение: ...<br>
<br>
Преимущества и особенности:<br>
- [Категория]: [краткое объяснение без нового абзаца]<br>
- [Категория]: [краткое объяснение без нового абзаца]<br>
- [Категория]: [краткое объяснение без нового абзаца]<br>
<br>
Идеальное решение для:<br>
- ...<br>
- ...<br>
- ...<br>
<br>
[Название товара] – это [итоговое резюме модели, ее пользы и сценариев применения без неподтвержденных обещаний].<br>

Примечание к шаблону: `[Название товара]` в первом и заключительном абзацах должен начинаться с заглавной буквы. В блоке «Преимущества и особенности» допустимо превращать подтвержденные характеристики в преимущества без числового перечисления, например: `Низкий уровень шума: помогает поддерживать комфортную атмосферу в помещении`. Саму строку примечания в итоговое описание не вставлять.

#### Если режим FILE:
- строить только на основе столбца **«Информация для описания»**
- не использовать интернет
- исходный текст из файла использовать только как материал для переработки
- результат обязан соответствовать полной структуре и правилам этого раздела
- не добавлять неподтвержденные свойства
- не придумывать недостающие возможности

#### Если режим WEB:
- формировать по интернет-правилам текущей задачи
- брать только подтвержденные свойства из реально найденных источников
- результат обязан соответствовать полной структуре и правилам этого раздела

#### Если режим MIXED:
- брать описание строго из того источника, который разрешил пользователь
- если карта источников для описания задает FILE → WEB, сначала использовать файл как исходный материал, а при его недостаточности добирать только разрешенные подтвержденные данные из интернета
- итоговое описание в любом случае должно быть единым переработанным текстом по стандарту этого раздела, а не смесью фрагментов без редактуры

### 7.8. Трубы
На итоговой вкладке поле **Диаметр труб хладагента [PROP_25]** должно быть:
- только в мм
- через /
- без пробелов
- с десятичной запятой

Если на вкладке Наполнение осталось дюймовое значение, этап считается невыполненным.

### 7.9. Габариты
Если исходный размер содержал дополнительное значение в скобках, например:
- `675(+57)×555×330`

то на итоговой вкладке:
- значение в скобках игнорируется
- итоговый формат записывается как:
  - `675x555x330` или в формате книги, принятом для соответствующего поля
- отдельные поля ширины / высоты / глубины должны быть заполнены значениями вне скобок
- полностью терять такое значение запрещено

### 7.9.1. Новые поля 52–56
Новые поля всегда должны присутствовать на итоговой вкладке «Наполнение» в точном порядке из раздела 7.2.

#### 7.9.1.1. Габариты панели
Поле **Габариты панели** заполняется только для:
- кассетных кондиционеров
- кассетных внутренних блоков

Правила:
- брать только подтвержденные размеры декоративной панели, а не габариты внутреннего блока
- если указаны и габариты блока, и габариты панели, не путать эти значения
- формат сохранять в мм в виде `ШxВxГ` или в формате исходной книги, если он уже принят для аналогичных размеров
- для настенных, канальных, напольно-потолочных, наружных блоков и обычных сплит-систем без отдельной кассетной панели поле оставлять пустым

#### 7.9.1.2. Напор воздуха
Поле **Напор воздуха** заполняется только для:
- канальных кондиционеров
- канальных внутренних блоков

Допустимые итоговые значения строго строчными буквами:
- `низконапорный`
- `средненапорный`
- `высоконапорный`

Правила определения:
- если тип напора прямо указан в источнике, перенести его в нормализованном виде строчными буквами
- если тип не указан, но есть статическое давление / внешний статический напор в Па, определить категорию по правилу:
  - до 50 Па включительно = `низконапорный`
  - 51–150 Па = `средненапорный`
  - более 150 Па = `высоконапорный`
- если указан диапазон Па и нет номинального значения, использовать верхнюю границу диапазона и зафиксировать это в Log
- для неканальных товаров поле оставлять пустым

#### 7.9.1.3. Категория
Поле **Категория** заполняется только для отдельных внутренних блоков и отдельных наружных блоков.

Допустимые итоговые значения строго строчными буквами:
- `внутренние блоки`
- `наружные блоки`

Правила:
- если товар является внутренним блоком, записать `внутренние блоки`
- если товар является наружным блоком, записать `наружные блоки`
- для комплектов кондиционеров, сплит-систем и мульти-сплит систем, которые не являются отдельным внутренним или наружным блоком, поле оставлять пустым

#### 7.9.1.4. Тип внутреннего блока
Поле **Тип внутреннего блока** заполняется для товаров, где есть внутренний блок или товар сам является внутренним блоком.

Итоговое значение всегда писать строчными буквами, например:
- `настенный`
- `кассетный`
- `канальный`
- `напольно-потолочный`
- `консольный`
- `колонный`

Правила:
- тип определять по подтвержденному описанию товара, серии, модели или характеристикам
- не писать с заглавной буквы
- не добавлять лишние слова вроде `кондиционер`, если достаточно типа блока
- для отдельных наружных блоков поле оставлять пустым

#### 7.9.1.5. Кол-во подключаемых блоков
Поле **Кол-во подключаемых блоков** заполняется только для наружных блоков.

Правила:
- указывать количество внутренних блоков, которые можно подключить к наружному блоку
- для мульти-сплит наружных блоков брать максимальное подтвержденное количество подключаемых внутренних блоков
- для обычного наружного блока, если он рассчитан на один внутренний блок и это подтверждено источником, можно указать `1`
- если количество не подтверждено, поле оставить пустым и объяснить причину в Log
- для внутренних блоков и комплектов кондиционеров поле оставлять пустым

### 7.10. Режим исключений перед финализацией
После первичного заполнения книги исполнитель обязан перейти в **режим исключений**.

В режиме исключений обязательно:
1. собрать список всех пустых полей по каждой строке
2. собрать список всех сомнительных и частично заполненных полей
3. по каждому такому полю указать:
   - проверено ли в файле
   - проверено ли в интернете, если интернет разрешен
   - найдено ли значение
   - почему оно осталось пустым
   - какой источник был последним проверенным
4. повторно добить поля, для которых значение найдено, но не было перенесено
5. только после завершения этого режима переходить к финальному аудиту

Запрещено:
- сначала назвать файл финальным, а потом искать причины пустых полей
- считать Log достаточным, если он не содержит явного списка исключений
- переходить к финализации раньше окончания режима исключений
- считать режим исключений завершенным, если интернет был разрешен, но по пустым и сомнительным полям не выполнен и не зафиксирован web-pass

### 7.11. Обязательная построчная сверка «источник → поле»
Перед завершением по каждой строке исполнитель обязан выполнить сверку:

- какие характеристики найдены в исходном тексте
- какие характеристики найдены в интернет-источниках, если интернет разрешен
- в какие конкретно итоговые поля они перенесены
- какие поля остались пустыми
- почему они пустые
- подтверждено ли, что в разрешенных источниках эти значения действительно не найдены или не поддаются надежному переносу
- если интернет был разрешен, отражен ли по каждому пустому полю выполненный web-pass и последний проверенный web-источник

Если найденная характеристика не сопоставлена с итоговым полем или объяснением в Log, строка считается незавершенной.

### 7.12. Высота строк
На вкладке «Наполнение» высота всех строк всегда = **15**.

## 8. Лист «Источники»

Создавать всегда.

Минимальные столбцы:
1. Наименование товара
2. Бренд
3. Модель
4. Сайт
5. URL
6. Что подтверждено / примечание

### 8.1. Если режим FILE
Для каждой строки:
- Сайт = Файл пользователя
- URL = пусто
- Примечание должно явно указывать:
  - характеристики взяты из «Характеристики»
  - описание переработано по стандарту раздела 7.7 на основе «Информация для описания»
  - техническая документация перенесена из «Техническая документация», если она была
  - если каких-то данных в файле не было — это нужно указать

### 8.2. Если режим WEB
Нужно отражать:
- основной сайт
- резервные сайты
- карточка точной модели или страница серии
- риски неполноты
- случаи добора ключевых полей
- какие вкладки и скрытые блоки были открыты
- сколько реально просмотрено доступных доменов по проблемным моделям
- были ли проверены приоритетные сайты и выполнено ли раскрытие блоков на них
- по каждой проблемной модели должна быть минимум одна web-строка; если значение не найдено, это тоже отражается как результат проверки с перечислением реально просмотренных доменов

### 8.3. Если режим MIXED
Нужно отражать и файл, и интернет-источники с пояснением, что именно откуда взято.

Если карта источников разрешает интернет хотя бы для части полей, лист «Источники» обязан содержать следы web-pass:
- какие поля ушли на web-проверку
- по каким моделям выполнялся web-добор
- какие домены реально просмотрены
- какие поля подтверждены web-источниками
- какие поля не удалось подтвердить даже после web-pass

### 8.4. Высота строк
На листе «Источники» высота всех строк всегда = **15**.

## 9. Лист «Log»

Создавать всегда.

Минимальные столбцы:
- Этап
- Проверка
- Правило
- Источник истины
- Статус
- Комментарий
- Исправление
- Финал

Допустимые статусы:
- Не начато
- В работе
- Выполнено
- Выполнено частично
- Требует исправления
- Невозможно выполнить

### 9.1. Обязательные проверки в Log
- Выбор режима источника
- Фиксация FILE / WEB / MIXED
- Проверка, что работа не началась до выбора режима
- Проверка, что интернет не использовался при FILE
- Проверка карты источников при MIXED
- Проверка чтения исходного Excel
- Проверка сохранения порядка строк
- Проверка листа «Сбор данных»
- Проверка листа «Нормализация»
- Проверка листа «Наполнение»
- Проверка листа «Источники»
- Проверка высоты строк = 15 на всех обязательных листах
- Проверка 56 столбцов на Наполнении
- Проверка полей из исходного Excel: Поставщик, Артикул, Сортировка, Цена
- Проверка источника характеристик
- Проверка источника описания
- Проверка, что описание не перенесено дословно
- Проверка структуры описания: вводный абзац → Основные характеристики → Преимущества и особенности → Идеальное решение для → заключение
- Проверка HTML-формата описания с использованием `<br>`
- Проверка отсутствия жирных выделений в описании
- Проверка заглавной буквы в начале «Наименование элемента» и «Детальное описание»
- Проверка заглавной буквы в полях «Бренд [BRAND]», «Серия [PROP_422]», значениях `В наличии` и `Китай`
- Проверка переноса TECH_DOCUMENTATION
- Проверка перевода труб в мм на Нормализации
- Проверка отсутствия дюймовых значений на Наполнении
- Проверка формата десятичного разделителя на Наполнении: точка для всех числовых характеристик, кроме поля «Диаметр труб хладагента»
- Проверка значения поля «Режим работы [PROP_423]» = `тепло-холод`
- Проверка значения поля «Инвертор [PROP_17]» только в нижнем регистре: `да` / `нет`
- Проверка, что «Наименование элемента» полное и не содержит название серии
- Проверка, что детальное описание не перечисляет технические характеристики табличным списком и использует их только как преимущества без числового дубляжа
- Проверка новых столбцов 52–56 и правил их применимости
- Проверка подсветки проблемных строк и пустых критичных ячеек
- Финальный аудит книги
- Проверка, что при разрешенном интернете web-pass действительно выполнен и отражен в Log
- Проверка, что при разрешенном интернете в листе «Источники» отражены web-источники по проблемным моделям

### 9.2. Дополнительные проверки для WEB
Если интернет разрешен, Log также обязан фиксировать:
- проверку точной карточки модели
- открытие вкладок «Характеристики» и «Описание»
- использование резервных источников при нехватке данных
- количество реально просмотренных доступных доменов по проблемным моделям
- достигнут ли стандарт углубленного поиска
- были ли проверены приоритетные сайты
- были ли раскрыты скрытые блоки и аккордеоны на приоритетных сайтах
- выполнена ли добивка пустых полей после web-поиска
- выполнен ли отдельный web-pass после разбора файла и первичного заполнения
- по каждому пустому или сомнительному полю указан ли последний проверенный web-источник
- отражены ли в Log реально просмотренные домены, а не только итог «найдено / не найдено»

### 9.3. Дополнительные проверки для антипропуска и антиошибочной финализации
Log обязан содержать отдельные строки проверки:
- Выполнен полный разбор всего текста характеристик
- Выполнен разбор внутреннего блока
- Выполнен разбор наружного блока
- Проверены охлаждение и обогрев отдельно
- Проверены средние значения против диапазонов
- Проверен тип хладагента
- Выполнен повторный проход по пустым полям
- Выполнен обязательный web-pass по пустым, сомнительным и частично заполненным полям
- Выполнено сравнение «данные в тексте → данные в итоговых полях»
- Для каждого пустого поля есть объяснение причины
- Сформирован список исключений до финализации
- Выполнен режим исключений
- Выполнена построчная сверка «источник → поле»
- Проверено, что аудит не декларативный, а выражен в явных проверках по строкам и полям
- Проверено, что файл не назван финальным при наличии необъясненных пустых полей
- Проверено, что модели одного типа и ряда не заполнены заметно слабее аналогичных без повторной проверки
- Проверено, что габариты панели заполнены только для кассетных моделей и кассетных внутренних блоков
- Проверено, что напор воздуха заполнен только для канальных моделей и канальных внутренних блоков и записан строчными значениями
- Проверено, что категория заполнена только для отдельных внутренних / наружных блоков и записана как `внутренние блоки` или `наружные блоки`
- Проверено, что тип внутреннего блока записан строчными буквами
- Проверено, что кол-во подключаемых блоков заполнено только для наружных блоков

Без этих записей аудит нельзя считать завершенным.

### 9.4. Высота строк
На листе «Log» высота всех строк всегда = **15**.

## 10. Проблемные товары и подсветка

Товар считается проблемным, если:
- нет цены
- нет детального описания
- описание не переработано по стандарту раздела 7.7
- описание не в HTML-формате с `<br>`
- наименование элемента или детальное описание начинается со строчной буквы
- в описании есть строка обычного текста, которая должна начинаться с заглавной буквы, но записана со строчной
- бренд, серия, `В наличии` или `Китай` записаны со строчной буквы
- в описании есть жирные выделения
- не хватает ключевых характеристик
- не выполнен перенос TECH_DOCUMENTATION при наличии HTML во входном файле
- трубы остались не в мм
- числовые характеристики на Наполнении с десятичной частью записаны не через точку, кроме поля «Диаметр труб хладагента»
- товар заметно менее заполнен, чем остальные
- у товара есть размеры внутреннего блока, но нет размеров наружного блока, хотя в тексте наружный блок указан
- есть охлаждение, но отсутствует обогрев / нагрев, хотя он указан в тексте
- есть диапазон температуры охлаждения, но отсутствует диапазон нагрева, хотя он указан в тексте
- есть размеры блока, но нет общего поля габаритов
- есть габариты наружного блока, но вес наружного блока пустой, хотя вес указан в тексте
- поле хладагента пустое, хотя в тексте есть R32 / R410A / другой тип
- в исходном тексте есть диаметр труб, а итоговое поле пустое
- в тексте есть потребляемая мощность, а поле «Номинальная мощность» пустое
- есть найденные характеристики, которые не сопоставлены ни с итоговым полем, ни с объяснением в Log
- второй проход по пустым полям не выполнен или выполнен не полностью
- список исключений не сформирован до финализации
- интернет был разрешен, но нет документированного web-pass
- интернет был разрешен, но по проблемной модели на листе «Источники» отсутствуют web-источники
- поле «Режим работы» заполнено иначе, чем `тепло-холод`
- поле «Инвертор» содержит значение не в нижнем регистре или не `да` / `нет`
- наименование элемента содержит название серии или не содержит полного обозначения модели
- детальное описание перечисляет уровень шума, напор воздуха, мощность, габариты или другие технические значения как характеристики вместо формулировки преимуществ
- новые поля 52–56 отсутствуют, стоят не в том порядке или заполнены для неприменимого типа товара
- габариты панели заполнены у некассетного товара или не заполнены у кассетного товара при наличии данных
- напор воздуха заполнен у неканального товара или не заполнен у канального товара при наличии данных
- категория заполнена у комплекта кондиционера либо не заполнена у отдельного внутреннего / наружного блока
- тип внутреннего блока записан с заглавной буквы или не заполнен при наличии внутреннего блока
- кол-во подключаемых блоков заполнено не у наружного блока либо не заполнено у наружного блока при наличии данных

Для проблемного товара:
1. вся строка — бледно-красная заливка
2. пустые критичные ячейки — ярко-красная заливка

## 11. Финальный запрет преждевременного завершения

Работу нельзя считать завершенной, если хотя бы одно из условий нарушено:
- режим источника не определен
- нарушен режим источника
- характеристики взяты не из разрешенного источника
- описание взято не из разрешенного источника
- описание перенесено дословно без переработки
- описание не приведено к структуре и правилам раздела 7.7
- описание не в HTML-формате с `<br>`
- наименование элемента или детальное описание начинается со строчной буквы
- в описании есть строка обычного текста, которая должна начинаться с заглавной буквы, но записана со строчной
- бренд, серия, `В наличии` или `Китай` записаны со строчной буквы
- в описании остались жирные выделения
- HTML из «Техническая документация» не перенесен при его наличии
- на вкладке Наполнение остались дюймовые значения труб
- на вкладке Наполнение числовые характеристики с десятичной частью записаны не через точку, кроме поля «Диаметр труб хладагента»
- при режиме WEB по проблемным моделям не зафиксирована глубина поиска
- Log не подтверждает проверку описания по стандарту
- Log не заполнен
- нарушены 56 столбцов
- высота строк на обязательных листах не равна 15
- не выполнен полный разбор текста по строкам товара
- не выполнен обязательный второй проход по пустым полям
- не сформирован список исключений до финализации
- не выполнена построчная сверка «источник → поле»
- есть хотя бы одно пустое поле без явного объяснения в Log
- есть найденная в тексте или интернете характеристика, которая не перенесена в итоговое поле и не объяснена в Log
- аудит выражен только общей формулировкой, а не явными проверками по строкам и полям
- файл объявлен финальным при наличии строк со статусом «Выполнено частично», «Требует исправления» или «Невозможно выполнить» без отдельного предупреждения
- модель одного типа или серии заполнена заметно слабее аналогичных, но не отправлена на повторную проверку
- при заданных пользователем приоритетных сайтах не подтверждено, что они были проверены первыми и просмотрены в глубину с раскрытием скрытых блоков
- интернет был разрешен, но отсутствует документированный web-pass по пустым, сомнительным и частично заполненным полям
- в листе «Источники» нет web-источников для проблемных моделей, хотя интернет был разрешен
- в Log отсутствует последний проверенный web-источник по полям, оставшимся пустыми после web-поиска
- задача фактически выполнена только по столбцу «Характеристики», хотя карта источников требует FILE→WEB или WEB-добор
- поле «Режим работы» заполнено не значением `тепло-холод`
- поле «Инвертор» заполнено не строчным значением `да` или `нет`
- наименование элемента содержит название серии, не является полным или начинается со строчной буквы
- детальное описание начинается со строчной буквы или содержит строки/абзацы, которые должны начинаться с заглавной буквы, но записаны со строчной
- бренд, серия, `В наличии` или `Китай` записаны со строчной буквы
- детальное описание содержит табличное перечисление характеристик товара вместо преимуществ
- отсутствуют столбцы 52–56 или нарушен их порядок
- новые поля 52–56 заполнены без учета типа товара или оставлены пустыми без объяснения при наличии подтвержденных данных

## 12. Сверхкраткая формула

1. Сначала спросить режим: FILE / WEB / MIXED
2. Зафиксировать режим в Log
3. Не нарушать выбранный режим
4. Сохранить исходный Excel и порядок строк
5. Сбор данных → Нормализация → Наполнение
6. До заполнения полей сделать полный разбор всего текста по строке
7. Отдельно проверить внутренний и наружный блок
8. Отдельно проверить охлаждение и нагрев / обогрев
9. Если есть и среднее значение, и диапазон — в числовое поле брать среднее
10. Всегда проверять тип хладагента
11. Трубы всегда перевести в мм
12. На Наполнении все числовые характеристики писать через точку, кроме труб — через запятую
13. Если размер записан со скобками, значение в скобках игнорировать
14. TECH_DOCUMENTATION переносить из файла, если HTML есть
15. Описание брать только из разрешенного источника, но всегда перерабатывать и приводить к стандарту раздела 7.7
16. Если интернет разрешен, после первичного заполнения обязательно выполнить отдельный документированный web-pass
17. После web-pass обязательно сделать второй проход по пустым полям
18. До финала обязательно сформировать список исключений
19. Перед завершением обязательно выполнить построчную сверку «источник → поле»
20. Создать Источники и Log
21. При разрешенном интернете зафиксировать в Log и на листе «Источники» реальные web-источники и последний проверенный источник по пустым полям
22. Не завершать работу без финального аудита, включая отдельную проверку описаний, пустых полей, web-pass и антипропускную проверку
23. Наименование элемента всегда делать полным, но без названия серии
24. Режим работы всегда записывать как `тепло-холод`
25. Инвертор всегда записывать строчными значениями `да` / `нет`
26. Детальное описание не должно перечислять технические характеристики товара; подтвержденные свойства использовать как преимущества без числового дубляжа
27. На итоговом листе обязательно держать 56 столбцов, включая последние пять: Габариты панели → Напор воздуха → Категория → Тип внутреннего блока → Кол-во подключаемых блоков
28. Новые пять полей заполнять только по применимости к типу товара и фиксировать неприменимость / отсутствие данных в Log
29. Наименование элемента и детальное описание всегда начинать с заглавной буквы; бренд и серию писать с заглавной буквы
30. Значения наличия писать как `В наличии`, а страну-изготовитель — как `Китай`
